# 合成证据资格基准 v2

**用途。** 在相同基础世界中，分别改变日期写法、就诊号编码、计量单位或指针分配，测量模型是否还能选择有资格的来源。这里报告数据构造与规则验收结果。v2 尚无模型预测或 RL 结果。

## 旧结果复核

用 v1 的生成器逐行还原公开预测 CSV 中对应的世界，按“合格指针、同字段坏指针”的有序对分组。训练支持取同情景的 8 个种子；留出世界按 CSV 的 `equal_value` 重建，因为不同数值版本可能消耗不同次数的随机抽样。下表单位为单侧决策，含 3 个模型及 2 个数值版本。

| 情景 | 训练见过该指针对 | 训练未见该指针对 |
|---|---:|---:|
| 单位缺失 | 174/192 | 8/48 |
| 过期 | 185/186 | 54/54 |
| 错就诊 | 240/240 | 无样本 |

单位缺失的准确率由 90.6% 降至 16.7%，支持策略依赖指针排布的解释。过期在这一拆分下答对全部未见组合，但旧任务只出现 0 天和 8 天。它不能区分模型学会了“同日”还是“含第 7 天的有效窗”。错就诊也没有覆盖未见指针对。[旧预测](EVIDENCE_HELD.csv)

## 数据与划分

每个字段有 2、3 或 4 个候选，恰有一个同时满足三条资格规则。两字段的候选数在同一世界中相等。BMI 和 MAP 均包含两个焦点字段、三个单缺陷和四个复合缺陷。每个训练缺陷组合有 320 个世界，两种计算器和两个焦点位置各占一半（两维交叉后每格 80 个）。干扰记录可同时违背多条规则。数值既有所有候选经后端解释后相等的世界，也有坏记录偏高或偏低的世界。训练和留出使用独立的随机种子区间。

| 分片 | 世界数 | 与哪个面板配对、改变什么 |
|---|---:|---|
| train | 2,240 | 训练使用 0、3、5 天的合格记录和 9、14 天的过期记录。BMI 使用 kg/lb 和 m/ft |
| iid | 2,240 | 新世界，沿用训练写法；其余面板均按 case 对齐这一参照 |
| age | 2,240 | 仅重编码日期。合格为 1、2、4、6、7 天，过期为 8、30 天 |
| encounter | 2,240 | 仅重编码就诊号。由 13 位十进制变为 11 位十六进制，当前和其他就诊均用同一格式 |
| unit | 1,120 | 仅重编码 BMI 有明确单位的记录，体重用 g、身高用 cm/in，并同步换算原始数值。对照为 iid 中相同的 1,120 个 BMI 世界 |
| pointer | 2,240 | 只重新分配记录 ID。记录顺序、字段、原始值、缺陷和正确物理量均相同 |

**指针留出的定义。** 将 e1/e2、e3/e4、e5/e6、e7/e8 定为保留组合，两个方向均计。训练时，任一合格记录与同字段任一干扰记录均不会组成保留组合。修订版训练时每个字段从每个保留组合各取一个成员。指针留出只交换记录 ID，使焦点有序对一定落入保留组合；4 候选时还会交换另一对，避免焦点组合成为字段内唯一成对的两条记录。每种计算器、焦点字段、缺陷组合和候选数下，每个可用指针作为焦点合格答案的次数相同。每个候选数下，面板内所有允许的焦点有序对也完全等频。训练和 pointer 两个集合即使忽略候选数，焦点有序对仍无交集。

**判分与分母。** 每个世界提供 6 个自然执行状态及 2 个重绑后的配对状态。其中自然 CALCULATE 来自 QUERY、BIND 各两次后；配对状态同预算、同反馈，只在实际绑定上不同。主要指标为自然 CALCULATE 准确率、配对两侧分别正确及两侧均正确率。按单缺陷和复合缺陷、字段、计算器、同值与异值分层。每个移位面板均应与相同 case 的 iid 结果做差，按训练种子配对，以基础世界为病例单位；各面板不可合并当作独立病例。训练拟合门槛仍为每个种子的全训练集命令准确率 ≥99%。

**覆盖边界。** 单位面板测量在新支持单位下的证据选择；算术由后端执行，选对记录不能证明模型会自行换算。单位缺陷在本版仍以缺单位表示。日期留出针对过去的时间窗。没有患者数据，基准也没有测量病历抽取能力。

## 数值格式修订与冻结

初版 `ca21f99` 在异值条件中给坏记录乘固定系数，使小数位数携带答案。冻结版从同一字段的相同物理量网格无放回采样，第一项用作合格值；同值条件复用第一项。所有记录均按八位小数显示，逐值断言转换完全精确。BMI 高度网格步长为 3/8 英寸，换算到 m、ft、cm 和 in 都可精确表示。这同时移除了即使末尾补零仍可识别的固定比例关系。

下表是异值世界中的字段选择准确率，两个字段均计分。平分时选显示顺序第一条。机会水平逐字段按 1/候选数计算。每个面板单独检查同值和异值，并同时检查所有字段和焦点字段两种分母。小数位最少、最小指针和第一条三项与机会水平相差超过 5 个百分点时构建失败。这是数据构造容差。日期新鲜度参与资格规则，单独报告其相关性。

| 面板 | 理论机会 | 小数位最少 | 最近日期 | 最小指针 | 第一条 |
|---|---:|---:|---:|---:|---:|
| train | 30.1% | 31.5% | 56.9% | 30.1% | 31.5% |
| iid | 30.0% | 29.4% | 58.3% | 29.9% | 29.4% |

六个面板中，三项非日期基线与机会值的最大绝对偏差为 1.96 个百分点（双字段）和 3.16 个百分点（仅焦点字段）。数值宽度全相同时，“小数位最少”与“第一条”按此平分规则必然一致。最近日期在异值 IID 可达 58.3%；因此总体准确率应同时与最近日期策略及各缺陷分层结果比较。该审计只覆盖列出的启发式规则。[全部 96 行分子、分母与差值](../fixtures/evidence-v2/shortcuts.csv)

## 奖励对照

原势能为每个字段的绑定质量（未绑 0、合格 +1、不合格 −1）求和，再除以两倍字段数。γ=1 时，从同一状态开始的两条轨迹，其势能差分之和仅由最终绑定决定。对全部 2,240 个训练世界，构造等成本路径，一条两次绑定同一合格记录，另一条先错绑再纠正。两条路径提交相同数值、结束于相同状态，累计势能奖励完全相等。逐次计数已接受的不合格 BIND，前者为 0，后者为 1。该检查说明二者在何种轨迹上可区分。

建议后续四组采用同一预热 checkpoint 配对、相同动作成本与 γ=1。记 R 为数值终局，Q 为最终势能，I 为当步工具接受了不合格绑定的指示量。

| 组 | 回报及信用 |
|---|---|
| A1 | R |
| A2 | R + αQ |
| A3 | 保留 A2，在每次事件发生处加 −λI；累计为 R + αQ − λΣI |
| A4 | 同 A3 奖励，加分叉与同状态相对信用，并匹配采样 token 预算 |

A2 对 A1 检查最终证据质量，尤其是错绑但数值相同的世界。A3 对 A2 识别引入路径代价的效果。仅用 episode 总回报训练 A3 时，该对比仍无法判定把信用精确分配到发生错误的动作是否有益；检验时间归因还需固定相同回报，同时比较错误时刻发放、延迟到终局及仅施加于错误动作优势这三种处理，见下表。A4 对 A3 检查额外信用机制。α、λ 和局部信用权重需在查看 v2 测试表现前锁定。

在 γ=1、一次错误位于 k 的例子中，下表列出该次惩罚对各位置的**原始附加项**（基线、归一化和 clipping 之前）。多次事件逐次相加。

| 做法 | 错误前的查询 | 错误绑定 k | 错误后的纠正 |
|---|---:|---:|---:|
| 错误时刻加奖励，后缀求和 | −λ | −λ | 0 |
| 同额奖励移到终局，后缀求和 | −λ | −λ | −λ |
| 仅在该动作的优势上加 −λIₖ | 0 | −λ | 0 |

前两者的差异发生在错误之后。第三种直接修改策略更新使用的优势，须在共同基线之后注入，并关闭会重新混合该附加项的跨步标准化。三者保持数值评分、最终证据质量、初始 checkpoint 及采样预算相同。当前证据是数据和信用定义的验收。模型训练效果仍待测量。

## 使用

[数据与逐分片计数](../fixtures/evidence-v2) · [环境、读取与状态构造](../medical/evidence.py) · [生成与验收脚本](../benchmarks/build_evidence_panels.py)

```python
from medical.evidence import decision_states, read_evidence_panel

for world, key in read_evidence_panel("fixtures/evidence-v2/pointer.jsonl.gz"):
    for role, observation, target in decision_states(world, key):
        # Only observation enters the policy. Keep role, target and key for scoring.
        pass
```

仓库根目录执行 `PYTHONPATH=. python benchmarks/build_evidence_panels.py /tmp/panels` 可重建分片。每行的 world 保存模拟器数据，key 保存独立计算的参考值、缺陷类型和来源指针；只有经过 QUERY 的记录进入模型观测。构建器逐例检查资格、规范化数值、配对干预、指针覆盖及训练提示与各留出提示的精确字符串交集。五个留出面板内部分别去重；同一基础世界在不同面板间有意复用。

## verl-agent 接口验收

`medical/evidence` 以冻结版 train 为训练池，验证选择五个留出分片之一。`medical/fhir` 保持合成训练池，用用户提供的 MedAgentBench v2 官方任务和评分器做验证。GET 只发往配置的基准 FHIR 服务，POST 沿用模拟接受语义。条件任务可切换官方奖励与已审计的患者/项目 GET 门控。运行时分别记录 agent 读取和评分器读取；门控检查成功的查询请求，尚不能证明策略理解了返回内容。计算任务接口当前只返回数值终局成功奖励，势能差另存于 info。

在独立的上游工作副本中应用 [注册补丁](../benchmarks/integration/register.patch)，将医学仓库根目录和上游仓库根目录加入 PYTHONPATH。trainer 的 `env.env_name` 选择对应接口，`+env.medical.fixtures` 指向已解压代码仓库中的分片目录。FHIR 验证另设 `+env.medical.upstream`、`+env.medical.fhir_base` 和可选的 `+env.medical.gated=true`。同一训练任务的多个 rollout 使用独立状态。验证默认重复固定的首个批次；全量评测须随每条数据传入 `env_kwargs.case_index` 并枚举各批次，避免重复首批。FHIR 使用最多 8 轮，需给包含函数清单和工具结果的观察预留 token 长度。

远程 CPU 验收使用上游原生 TrajectoryCollector、真实 tokenizer 和脚本动作。两个计算 episode 均在 6 步完成。两个虚构 FHIR 查询 episode 经过环回 HTTP GET 并由官方 task1 评分器判为成功。官方 task5 评分器也在虚构病例上执行了自己的查询，空提交在读取门控下被拒绝，agent 亲自发出匹配查询后同一提交通过。本次没有使用模型策略或完整 FHIR 服务评测官方 300 题。[接口](../medical/verl_env.py) · [验收入口](../benchmarks/integration/check_rollout.py)
