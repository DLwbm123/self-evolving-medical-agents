# 24 个预热适配器的逐步诊断

现有 24 个模型均未同时达到正常路径逐步准确率 95% 和贪心完成率 90%。同一正确轨迹监督条件下，仅三个初始化的表现就能相差很大。现有结果不能确定恢复监督对新初始化有稳定的收益或损害。

**评估口径修订。** 表中的离轨状态只改变提示中的反馈或预算，底层证据未被破坏。首步所有 36 个留出提示都在训练中出现过，原始表保留用作历史记录。按两个监督组共享的未见状态重新计分，并按扰动类型及正常路径准确率控制后的结果，见[证据资格与绑定纠正](EVIDENCE_QUALIFICATION.md)。

## 评估设计

每个适配器恢复对应的 Qwen2.5-0.5B-Instruct 基座和 LoRA 参数，在 CUDA BF16 eval 模式下执行前向。只比较当前菜单里合法字母的 logits，取 argmax。每个模型分别评估：

- 192 个实际监督样本，保留原来的重复和预算。
- 36 个独立留出病例，每例沿正确路径提供六个状态，共 216 次判断。
- 相同留出病例，每例分别执行一次过早计算、重复查询和错绑证据，仅取各次错误之后的第一个状态，共 108 次判断。
- 在同一批 36 个留出病例上独立执行完整贪心轨迹。从每个病例初始状态出发，直到 FINISH 或耗尽预算。

逐步评估同时使用原菜单和三个新排列种子 101、102、103。新排列由可见状态与种子决定，教师目标按实际命令重新映射。表中准确率为精确匹配教师命令。第一步先查另一个尚未查询的字段也可能合理，所以详细表另计能推进任务的合法动作。原菜单的训练准确率包含训练中见过的状态；样本数不能解释为独立病例数。学习率或模型规模造成的影响尚未做因果检验。

表格是三个训练种子的等权平均，单位为百分比。前三列使用各模型训练时的菜单规则。最后一列为三个额外排序种子下的正常路径平均值。

原版两种监督的正常路径准确率已相差 54.4 个百分点，直接比较离轨准确率无法识别专属的恢复能力。三个初始化的病例共享相同留出面板。各初始化的分数保留在 CSV 中；对“训练种子是最大的方差来源”仍需要明确的方差分解和更多独立训练。

## 原版正确轨迹组的 MAP 失败定位

每个种子有 18 个 MAP 留出病例。三个种子的第一步都精确命中 18/18，第二步绑定分别命中 2/18、5/18、2/18；允许查询另一个缺失字段等合理动作后，第二步分别有 6/18、9/18、6/18 次推进任务。第 3 至 5 步在每个种子上各命中 3/18，即使人工提供正确前缀，后续动作仍持续出错。

第 2 至 6 步合计 90 个参考状态，教师字母 A 只出现 12 次。种子 0、1、2 分别选 A 90、78、75 次。该组在原生菜单和这些 MAP 状态上呈现具体的位置偏好。最好的一次训练来自原版恢复组，留出正常路径为 194/216，贪心完成 31/36。最后一批的低 loss 与整体过线是两个独立读数。

## 复算

在配有基座及适配器的 GPU 服务器上，从仓库根目录执行以下命令。ADAPTER_RUNS 的子目录沿用 budget 消融布局，包含监督条件、模式、种子和 adapter。汇总器从原始训练日志提取第 72 次更新前最后一个 minibatch 的 loss。末批 loss 使用训练日志中的记录精度。

```sh
export PYTHONPATH=.
python benchmarks/score_steps.py "$MODEL" "$ADAPTER_RUNS" runs/steps --side 0
python benchmarks/score_steps.py "$MODEL" "$ADAPTER_RUNS" runs/steps --side 1
python benchmarks/report_steps.py runs/steps "$ADAPTER_RUNS" reports
```
